# Visual Plan (local)

`visual-plan` writes a **self-contained HTML plan page** to
`{CHANGE-ID}/planning/plan.html` when the task-plan-evaluator returns **PASS**,
then opens it in a **new browser tab**.  The workflow continues immediately — it
does not wait for the user to close the tab.

## What the plan contains

| Section | Content |
|---|---|
| **Header** | Change ID, story title, APPROVED badge |
| **Goal** | `story.yaml` goal / description field |
| **Task cards** | All tasks from `planning/tasks.yaml` — ID, title, description, dependency list |
| **AC coverage table** | Each acceptance criterion from `story.yaml` with the tasks that cover it |

## Implementation

The plan is generated by **`core/visual_artifacts.generate_plan_html(change_id)`**
called from `core/steps.step_task_gen_evaluator()` inside the `if passed:` branch
(after `passed = "PASS" in result`).
Browser open uses `core/visual_artifacts.open_in_browser(path, new_tab=True)`.
`new_tab=True` maps to `webbrowser.open(..., new=2)`.

Both calls are wrapped in `try/except` — a failure to generate or open the HTML
is logged and ignored; the workflow result and `return result` are unaffected.

### Data sources

| File | Used for |
|---|---|
| `{CHANGE-ID}/intake/story.yaml` | Title, goal, acceptance criteria |
| `{CHANGE-ID}/planning/tasks.yaml` | Task list (`tasks[*]`) — id, title, description, depends_on |

### Browser-open guard

Same guard as the visual-recap skill:

| Env / condition | Behaviour |
|---|---|
| `WORKBENCH_OPEN_BROWSER=1` | Always open |
| `WORKBENCH_OPEN_BROWSER=0` | Always suppress |
| `CI` set | Suppress |
| Non-tty stdout | Suppress |
| Default (interactive tty) | Open |

## Structure reference

Page layout follows the [BuilderIO visual-plan skill](https://github.com/BuilderIO/skills/tree/main/skills/visual-plan)
— dark-mode, card-based task breakdown, dependency annotations, and AC-coverage
table — rendered as a zero-dependency inline-CSS HTML file rather than as a
hosted Agent-Native Plan.
