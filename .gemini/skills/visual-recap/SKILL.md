# Visual Recap (local)

`visual-recap` writes a **self-contained HTML recap page** to
`{CHANGE-ID}/pr/recap.html` immediately after the Azure DevOps pull request is
created, then opens it in the user's default browser.

## What the recap contains

| Section | Content |
|---|---|
| **PR banner** | PR title, badge with PR ID, and a **direct clickable link** to the ADO pull request |
| **Changed files** | File map from `git diff --name-status develop...HEAD` with add/modify/delete labels |
| **Implementation summaries** | Status and summary from each `execution/*/impl_report.yaml` |
| **QA summary** | Overall result from `qa/qa_report.yaml` |

## Implementation

The recap is generated by **`core/visual_artifacts.generate_recap_html(change_id, repo, pr_payload)`**
called from `core/steps.step_pr_review()` immediately after `_create_ado_pull_request()`.
Browser open uses `core/visual_artifacts.open_in_browser(path, new_tab=False)`.

### PR link requirement

The recap **MUST** include a direct link to the pull request.  The `pr_web_url(pr_payload)`
helper derives the URL in this order:
1. `repository.webUrl + "/pullrequest/" + pullRequestId` (preferred)
2. `_links.web.href` (fallback for some az CLI versions)
3. Empty string — recap will note the URL is unavailable

### Browser-open guard

| Env / condition | Behaviour |
|---|---|
| `WORKBENCH_OPEN_BROWSER=1` | Always open |
| `WORKBENCH_OPEN_BROWSER=0` | Always suppress |
| `CI` set | Suppress |
| Non-tty stdout | Suppress |
| Default (interactive tty) | Open |

## Structure reference

Page layout follows the [BuilderIO visual-recap skill](https://github.com/BuilderIO/skills/tree/main/skills/visual-recap)
— dark-mode, card-based layout, file tree, and change annotations — rendered as
a zero-dependency inline-CSS HTML file rather than as a hosted Agent-Native Plan.
