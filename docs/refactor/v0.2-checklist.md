# v0.2 "Measurable Workbench" Checklist

Tracks closure of each numbered prompt in the v0.2 refactor. A prompt is checked only when its
deliverables are implemented, tested, documented, and (for Prompt 7) audited.

- [x] **Prompt 1** — Benchmark inventory foundations.
- [x] **Prompt 2** — Versioned evaluation report contract (`eval/report_schema.py`,
  `report_schema_version = "0.2"`, `Metric`/`MetricStatus` honesty flags).
- [x] **Prompt 3** — Live report generation wired into the runner (`eval/live_report.py`,
  per-AC results, scorecard).
- [x] **Prompt 4** — Canonical local JSONL trace contract (`telemetry/events.py`,
  `docs/tracing.md`).
- [x] **Prompt 5** — Baseline-vs-candidate comparison and regression classification
  (`eval/comparison.py`, `eval/classification.py`, `eval/comparison_schema.py`,
  `eval/comparison_policy.py`, `eval/render_comparison.py`).
- [x] **Prompt 6** — v0.2 report contract wired into the live eval runner end to end.
- [x] **Prompt 7** — v0.2 CI surface, documentation, and closure.
  - [x] `eval/exit_codes.py` — centralized exit-code contract (0/2/3/4/5/6).
  - [x] `eval/render_report.py` — human-readable single-report summary
    (`render_eval_summary`), reading only canonical `EvalReport` fields.
  - [x] `eval/cli.py` — `python -m eval.cli` command surface: `run`, `baseline`, `compare`,
    `ci`. Orchestrates existing `eval.runner`/`eval.comparison` APIs; no reimplementation of
    scoring, comparison, or classification logic.
  - [x] Optional-integration isolation verified: the CLI and report renderer import neither
    Opik nor the server; `tests/test_cli_isolation.py` and
    `tests/test_v02_end_to_end.py::IsolationScenarioTests` prove commands work with those
    imports actively blocked.
  - [x] Fixtures added under `tests/fixtures/eval/suite/` (legacy `story.json`/
    `hidden_tests.py` case and a manifest-shaped case) to exercise the CLI path end to end.
  - [x] `tests/test_eval_cli.py` — argument parsing and exit-code unit tests.
  - [x] `tests/test_v02_end_to_end.py` — all 20 documented end-to-end scenarios, driven
    in-process through `eval.cli.main(argv)`, deterministic and LLM-free.
  - [x] `tests/test_render_report.py` — rendering tests, including unavailable-metric honesty
    (never coerced to `0`).
  - [x] `docs/evaluation.md` — primary CLI guide: workflows, exit-code table, evidence
    inspection, benchmark authoring, missing-metric semantics, Opik/server-free operation.
  - [x] `docs/refactor/v0.2-acceptance-audit.json` / `.md` — all 16 `AC-v0.2-01`..`16`
    entries recorded `pass`, each with implementation + test + documentation evidence that
    resolves to real, collectable artifacts.
  - [x] `tests/test_v02_acceptance_audit.py` — machine-verifies the audit JSON itself (all AC
    IDs present, no duplicates, valid statuses, evidence paths exist, every `test::<node_id>`
    evidence entry collects to exactly one pytest item).
  - [x] Acceptance audit passed in full (`overall_status: "pass"`, zero `fail` entries) —
    Prompt 7 checked above on that basis.
