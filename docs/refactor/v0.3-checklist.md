# v0.3 "Explicit Workflow Runner" Checklist

Tracks closure of each numbered prompt in the v0.3 refactor. A prompt is checked
only when its deliverables are implemented, tested, documented, and (for Prompt 11)
audited. Unlike v0.2, v0.3 shipped without committed acceptance-criteria artifacts —
it was tracked only by prompt number — so Prompt 11 reconstructs the audit against
the canonical AC-v0.3-01..17 list.

- [x] **Prompt 8** — `WorkflowRunner` shell: the explicit, typed boundary
      `RunSpec -> WorkflowRunner -> run.py::main -> WorkflowResult`
      (`workflow/models.py`: `RunSpec`, `RunContext`, `WorkflowResult`, `FailureDetail`,
      `RunStatus`; `workflow/runner.py`: `WorkflowRunner`, `_default_legacy_workflow`).
      Import isolation verified (`tests/test_workflow_isolation.py`); documented in
      `docs/workflow-runner.md`.
- [x] **Prompt 9** — Explicit per-stage execution contracts
      (`workflow/stages.py`: `WorkflowStage` protocol, `CallableStage`, `StageResult`,
      `StageFailure`, `StageStatus`). Canonical `stage.started`/`stage.completed`/
      `stage.failed` lifecycle events emitted through the Prompt-4 `telemetry` contract
      via a caller-supplied `EventSink`. Stages testable in isolation
      (`tests/test_workflow_stages.py`, `tests/test_workflow_stage_isolation.py`);
      documented in `docs/workflow-stages.md`.
- [x] **Prompt 10** — Entry points routed through the shared runner boundary:
      `run.py::run_spec_from_args` / `run.py::execute_cli_args` make `__main__` a thin
      adapter over `WorkflowRunner`; `eval/runner.py` and `server/runner_proc.py`
      reach the same `run.py` CLI adapter via subprocess flags without re-implementing
      its argument mapping. Characterized by `tests/test_workflow_cli_adapter.py`,
      `tests/test_workflow_eval_adapter.py`, `tests/test_workflow_server_adapter.py`.
- [x] **Prompt 11** — v0.3 acceptance audit and closure.
  - [x] `docs/refactor/v0.3-acceptance-audit.json` — machine-readable source of truth,
        AC-v0.3-01..17 all `pass`, `overall_status: pass`.
  - [x] `docs/refactor/v0.3-acceptance-audit.md` — human-readable mirror generated from
        the JSON.
  - [x] `tests/test_v03_acceptance_audit.py` — deterministic machine verifier: every AC
        id present once, statuses valid, `pass` entries carry evidence, plain paths exist
        on disk, every `tests/…::node_id` collects to exactly one pytest item,
        `overall_status` is `pass`.
  - [x] No production behavior change: `workflow/*.py`, `run.py`, `core/*`, `server/*`,
        `eval/*`, prompts, loop policies, and workflow order are untouched.

## Deferred (documented, not silently claimed)

Two criteria pass at the contract + test level with an honest audit note:

- **AC-v0.3-07** — canonical `stage.*` lifecycle events are emitted only by
  `CallableStage` (exercised by tests). Production `run.py::_Stage` still emits its own
  legacy `stage.start`/`stage.end` pair; no production `_Stage` call site is wrapped by
  `CallableStage`. This integration seam was deliberately deferred by Prompts 9/10 (see
  `docs/workflow-stages.md`) and is not demanded by any AC. Wiring it would be a behavior
  change, out of scope for this closure.
- **AC-v0.3-09** — eval reaches `WorkflowRunner` transitively through the `run.py`
  subprocess boundary, not by importing it in-process (`eval.runner` has no such import).
  This is deliberate process isolation, not a direct call.

## Not in v0.3 (out of scope for this checklist)

- Wiring `WorkflowStage`/`CallableStage` into production `run.py::_Stage` call sites.
- Adding `WorkflowResult.stage_results`.
- Pluggable runner backends / formal artifact contracts (v0.4 and beyond).
