# v0.4 "Clean Runner and Artifact Layer" Checklist

Tracks closure of each numbered prompt in the v0.4 refactor. A prompt is checked
only when its deliverables are implemented, tested, documented, and (for Prompt 24)
audited. The canonical acceptance criteria are `AC-v0.4-01..20`; the machine-readable
source of truth is `docs/refactor/v0.4-acceptance-audit.json`, mirrored by
`docs/refactor/v0.4-acceptance-audit.md` and verified by
`tests/test_v04_acceptance_audit.py`.

Prompt numbers below follow the merge history (`Merge Prompt 12`..`Merge Prompt 16`
are explicit; later prompts are matched to their feature commits and the criteria
they delivered).

- [x] **Prompt 12** — Agent invocation + result contracts
      (`runners/models.py`: `AgentInvocation`, `AgentResult`). Frozen backend-agnostic
      request; result keeps unknown tokens/cost as `None` (omitted, not fabricated).
      Documented in `docs/agent-invocation-contract.md`. (AC-v0.4-01, AC-v0.4-02)
- [x] **Prompt 13** — Runner backend execution boundary
      (`runners/base.py`: `RunnerBackend`, abstract `invoke(AgentInvocation) -> AgentResult`).
      Cannot be instantiated directly; subclass missing `invoke` cannot instantiate.
      Documented in `docs/runner-backend-interface.md`. (AC-v0.4-03)
- [x] **Prompt 14** — Concrete runner backend adapters
      (`runners/{claude,codex,copilot,gemini,omp,openai_compat,legacy}.py`). Every runtime
      backend plus the legacy dispatch fallback implements `RunnerBackend`; argument/model
      passthrough and alias resolution characterized. Documented in
      `docs/runner-backend-adapters.md`. (AC-v0.4-04)
- [x] **Prompt 15** — Centralized runner backend registry
      (`runners/registry.py`: `RunnerRegistry` with lazy factories and structured
      `UnknownRunnerError` / `InvalidRunnerNameError` / `RegistryConfigurationError`).
      Documented in `docs/runner-registry.md`. (AC-v0.4-05)
- [x] **Prompt 16** — Isolated runner failover policy
      (`runners/failover.py`: `FailoverPlan`, `FailoverExecutor`). Layered over the
      registry; later routes resolved lazily and never on success. Documented in
      `docs/runner-failover.md`. (AC-v0.4-06)
- [x] **Prompt 17** — Runner lifecycle events and safe hash capture
      (`runners/lifecycle.py`: `InstrumentedRunnerBackend`, `_sha256_text`). Exactly one
      `started` + one terminal `completed`/`failed`/`timed_out` event through the canonical
      `telemetry` `EventType` contract; prompt/response reduced to SHA-256 with raw text
      never emitted; fake/recording backends drive the suite. Documented in
      `docs/runner-lifecycle-events.md`. (AC-v0.4-07, AC-v0.4-08, AC-v0.4-09)
- [x] **Prompt 18** — Versioned `ArtifactRef` contract
      (`artifacts/models.py`: `ArtifactRef`). Immutable typed reference with deterministic
      `to_dict`/`to_json`, lossless round trip, and deeply-immutable JSON-safe metadata.
      Documented in `docs/artifact-ref.md`. (AC-v0.4-10)
- [x] **Prompt 19** — Payload contracts and structured validation
      (`artifacts/payloads.py` planning payloads with `ImplementationReportPayload` /
      `QAReportPayload` alias identity; `artifacts/validation.py`: `ValidationResult`,
      `ArtifactLoadError`, `ArtifactValidationError`). `validate_payload` never raises on
      domain errors; `load` raises structured errors. Documented in
      `docs/artifact-payload-contracts.md`. (AC-v0.4-11, AC-v0.4-12)
- [x] **Prompt 20** — Evidence artifact contracts and centralized paths
      (`artifacts/evidence.py`: `FinalDiffArtifact`; `eval/report_artifact.py`:
      `EvalReportArtifact`; `telemetry/trace_artifact.py`: `TraceArtifact`;
      `eval/evidence_artifacts.py`: `EVIDENCE_ARTIFACTS`; `eval/evidence_paths.py`:
      `TrialEvidencePaths`). Evidence/report/trace expose `to_artifact_ref`; evidence path

      `docs/evidence-artifact-contracts.md`. (AC-v0.4-16, AC-v0.4-17)
- [x] **Prompt 21** — Stage artifact declarations and lifecycle events
      (`workflow/stage_artifacts.py`: `StageArtifactDeclaration`, `Cardinality`,
      `validate_stage_artifacts`; `workflow/artifact_lifecycle.py`:
      `emit_stage_artifact_lifecycle`). Each canonical stage declares consumed/produced

- [x] **Prompt 22** — Complete artifact lifecycle integration coverage

## Cross-cutting invariants (maintained across Prompts 12-23, audited by Prompt 24)

These criteria are not owned by a single prompt; every prompt upheld them and Prompt 24
consolidates the audit:

- **AC-v0.4-18** — optional dependencies isolated: fresh-subprocess import probes assert the
  runner and artifact contracts import without pulling in `server`, `opik`, `fastmcp`, or
  vendor SDKs (`tests/test_runners_isolation.py`, `tests/test_artifact_ref_isolation.py`,
  `tests/test_live_workflow_artifacts_isolation.py`, `tests/test_workflow_isolation.py`).
- **AC-v0.4-19** — the runner, artifact, stage, and workflow contracts are covered by a broad
  fake-backed and isolation-probed suite.
- **AC-v0.4-20** — every runner and artifact contract is documented under `docs/`, and this
  closure ships the audit JSON + Markdown mirror + this checklist.

## Deferred (documented, not silently claimed)

Three criteria pass at the contract + boundary level with an honest audit note (see the
"Documented exceptions / deferred boundaries" section of `docs/refactor/v0.4-acceptance-audit.md`):

- **AC-v0.4-15** — typed loaders/collector are adopted at the live workflow boundaries
  (`LiveArtifactCollector`); wholesale deletion of every historical ad-hoc parser is a
  deferred cleanup, not part of this milestone.
- **AC-v0.4-16** — centralized, traversal-safe evidence path resolution lives in
  `eval/evidence_paths.py::TrialEvidencePaths` (with per-stage helpers in `core/steps.py`),
  not in `artifacts/evidence.py`.
- **AC-v0.4-17** — eval reports/evidence expose `ArtifactRef` at the contract + boundary level
  (`to_artifact_ref` registered via `EVIDENCE_ARTIFACTS`); a full runtime migration of every
  historical eval-report writer is deferred.

## Not in v0.4 (out of scope for this checklist)

- v0.5 eval productization (turning the eval harness into a supported product surface).
- Benchmark expansion beyond the hermetic fixtures / generated benchmark set.
- Broad cleanup of remaining historical ad-hoc parsers and eval-report writers (the deferred
  boundaries above).

## Branch policy

All v0.4 work — Prompts 12-24 — lands on the single long-lived branch
`feature/refactor-to-v1`. Prompt 24 is one commit on that branch,
`Close v0.4 runner and artifact milestone`; the hermetic fixture repair is recorded here as
closure / test-infrastructure work, not a production behavior change.
